# Remember

Use the configured `basic-memory` MCP server and project `knowledge` at https://bm.asylcreek.xyz/mcp.

Do not capture automatically, save whole transcripts, or perform startup or background memory work. If the server is unavailable, report that saving did not complete.

1. Identify what the user asked to preserve. Use the current conversation and its evidence. Do not invent missing causes, results, commands, or verification.
2. Search for an existing record about the same issue. Update it rather than creating a duplicate. Read the current revision before editing and respect any conflict returned by the server.
3. Save a concise, self-contained Markdown record. Include the problem and environment, confirmed findings, relevant failed attempts, the exact fix, verification, rollback when known, and remaining uncertainty. Add the date and a source conversation link or artifact path when available. Omit empty sections and unrelated transcript detail.
4. Keep observations distinct from hypotheses. Commands and configuration that were proposed but never applied must remain labeled as proposed. Never store passwords, tokens, private keys, or other secrets.
5. Read back the saved record and report its title and memory URL. If saving fails, report the failure rather than claiming the fact was remembered.

The MCP server is the authority for tool names and arguments; use its advertised search/read/write/edit tools.

Do not modify the system being documented or write to other memory systems as part of this skill.
